## Шаг 1: Установка Node.js

### Что такое Node.js?
Node.js - это программа, которая позволяет запускать JavaScript на вашем компьютере. Она нужна для работы с нашим проектом.

### Как установить:

1. Перейдите на сайт [nodejs.org](https://nodejs.org/)
2. Скачайте версию LTS (Long Term Support) - это стабильная версия
3. Запустите установщик и следуйте инструкциям
4. **Важно**: При установке убедитесь, что отмечена опция "Add to PATH"

### Проверка установки:

Откройте PowerShell (Windows) или Terminal (Mac/Linux) и выполните:
```bash
node --version
npm --version
```

Если вы видите номера версий (например, `v20.10.0`), значит всё установлено правильно! ✅

## Шаг 3: Настройка Supabase

### Что такое Supabase?
Supabase - это база данных в облаке. Здесь мы будем хранить результаты тестов пользователей.

### Создание проекта:

1. Перейдите на [supabase.com](https://supabase.com)
2. Войдите в свой аккаунт (или зарегистрируйтесь)
3. Нажмите **"New Project"** (зеленая кнопка справа вверху)

4. **Заполните форму**:
   - **Organization**: выберите вашу организацию (или создайте новую)
   - **Name**: `burns-test` (или любое другое имя)
   - **Database Password**: придумайте надежный пароль
     - ⚠️ **ВАЖНО**: Сохраните этот пароль! Он понадобится для доступа к базе данных
   - **Region**: выберите ближайший регион (например, "West US" или "Europe West")
   - **Pricing Plan**: выберите "Free" (бесплатный план)

5. Нажмите **"Create new project"**
6. Подождите 2-3 минуты, пока проект создается

### Получение ключей API:

1. В вашем проекте Supabase найдите в левом меню **"Settings"** (шестеренка)
2. Нажмите **"API"** в подменю
3. Найдите раздел **"Project API keys"**

4. **Скопируйте два значения**:
   - **Project URL** - это длинный адрес вида `https://xxxxx.supabase.co`
   - **anon public** ключ - это длинная строка из букв и цифр

### Создание таблицы в базе данных:

1. В левом меню Supabase найдите **"SQL Editor"**
2. Нажмите **"New query"**
3. Откройте файл `supabase_setup.sql` в вашем проекте (в папке проекта)
4. **Скопируйте весь текст** из этого файла
5. **Вставьте** в SQL Editor в Supabase
6. Нажмите **"Run"** (или Ctrl+Enter)

Вы должны увидеть сообщение "Success. No rows returned" - это значит, что таблица создана! ✅

### Проверка таблицы:

1. В левом меню найдите **"Table Editor"**
2. Вы должны увидеть таблицу `test_results`
3. Таблица пока пустая - это нормально, данные появятся после первого прохождения теста

## Шаг 4: Настройка переменных окружения

### Что это такое?
Переменные окружения - это секретные данные (ключи, пароли), которые нужны приложению, но не должны быть видны в коде.

### Инструкция:

1. В папке проекта найдите файл `.env.example`
2. **Скопируйте его** и переименуйте в `.env` (уберите `.example`)
   - В Windows: кликните правой кнопкой → "Переименовать"
   - Или в PowerShell: `Copy-Item .env.example .env`

3. **Откройте файл `.env`** в любом текстовом редакторе (Блокнот, VS Code)

4. **Замените значения**:
```
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_ANON_KEY=ваш_anon_ключ_из_supabase
```

Где взять эти значения? Из шага 3 (настройка Supabase)!

**Пример:**
```
VITE_SUPABASE_URL=https://abcdefghijklmnop.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6ImFiY2RlZmdoaWprbG1ub3AiLCJyb2xlIjoiYW5vbiIsImlhdCI6MTYzODk2NzI4MCwiZXhwIjoxOTU0NTQzMjgwfQ.abcdefghijklmnopqrstuvwxyz1234567890
```

5. **Сохраните файл** (Ctrl+S)

## Шаг 5: Тестирование локально

### Проверка работы приложения:

1. **Запустите приложение**:
```bash
npm run dev
```

2. Откройте браузер и перейдите на `http://localhost:3000`

3. **Что вы должны увидеть**:
   - Экран с первым вопросом теста
   - Кнопки с вариантами ответов (Никогда, Редко, Иногда, Часто, Постоянно)
   - Кнопки "Назад" и "Далее"

4. **Пройдите тест**:
   - Выберите ответ на каждый вопрос
   - Нажимайте "Далее" для перехода к следующему вопросу

   - Должен появиться экран с результатом
   - Нажмите "Посмотреть динамику"
   - Должен появиться график (если это не первый тест)

6. **Проверьте базу данных**:
   - Вернитесь в Supabase → Table Editor → test_results
   - Вы должны увидеть новую запись с результатом теста!

**Если всё работает - отлично! Переходим к следующему шагу.** ✅

## Шаг 6: Загрузка в GitHub

### Что такое GitHub?
GitHub - это место, где хранится код проекта. Vercel будет брать код оттуда для развертывания.

### Инструкция:

1. **Откройте GitHub** в браузере и войдите в аккаунт

2. **Создайте новый репозиторий**:
   - Нажмите зеленую кнопку "New" (или "+" → "New repository")
   - **Repository name**: `burns-test-miniapp` (или любое другое имя)
   - Выберите **Public** (публичный)
   - **НЕ** отмечайте "Add a README file" (у нас уже есть README)
   - Нажмите **"Create repository"**

3. **Загрузите код в репозиторий**:

Откройте PowerShell в папке проекта и выполните:

```bash
# Инициализация Git (если еще не сделано)
git init

# Добавление всех файлов
git add .

# Создание первого коммита
git commit -m "Initial commit: Burns depression test mini app"

# Добавление удаленного репозитория (замените YOUR_USERNAME на ваш username GitHub)
git remote add origin https://github.com/YOUR_USERNAME/burns-test-miniapp.git

# Загрузка кода
git branch -M main
git push -u origin main
```

**Важно**: Замените `YOUR_USERNAME` на ваш реальный username GitHub!

**Пример**:
```bash
git remote add origin https://github.com/maxse/burns-test-miniapp.git
```

Если Git попросит ввести логин и пароль:
- Логин: ваш username GitHub
- Пароль: используйте Personal Access Token (см. ниже)

### Создание Personal Access Token (если нужно):

1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. Generate new token (classic)
3. Название: `vercel-deploy`
4. Выберите срок действия (например, 90 days)
5. Отметьте `repo` (все права на репозитории)
6. Generate token
7. **Скопируйте токен** (он показывается только один раз!)
8. Используйте этот токен как пароль при `git push`

## Шаг 7: Развертывание на Vercel

### Что такое Vercel?
Vercel - это платформа, которая размещает ваше приложение в интернете. После развертывания у вас будет свой адрес (например, `burns-test.vercel.app`).

### Инструкция:

1. **Перейдите на [vercel.com](https://vercel.com)** и войдите через GitHub

2. **Создайте новый проект**:
   - Нажмите **"Add New..."** → **"Project"**
   - Найдите ваш репозиторий `burns-test-miniapp` в списке
   - Нажмите **"Import"**

3. **Настройка проекта**:
   - **Framework Preset**: Vite (должно определиться автоматически)
   - **Root Directory**: `./` (оставьте как есть)
   - **Build Command**: `npm run build` (должно быть по умолчанию)
   - **Output Directory**: `dist` (должно быть по умолчанию)

4. **Добавление переменных окружения**:
   
   В разделе **"Environment Variables"** добавьте две переменные:

   **Первая переменная:**
   - **Key**: `VITE_SUPABASE_URL`
   - **Value**: ваш URL из Supabase (из шага 3)
   - Отметьте все три галочки: ☑ Production ☑ Preview ☑ Development

   **Вторая переменная:**
   - **Key**: `VITE_SUPABASE_ANON_KEY`
   - **Value**: ваш anon key из Supabase (из шага 3)
   - Отметьте все три галочки: ☑ Production ☑ Preview ☑ Development

5. **Развертывание**:
   - Нажмите **"Deploy"**
   - Подождите 2-3 минуты

6. **Получение URL**:
   - После успешного развертывания вы увидите зеленую галочку ✅
   - Скопируйте **URL** (например, `https://burns-test-miniapp.vercel.app`)
   - Этот URL понадобится для настройки бота!

## Шаг 8: Настройка Telegram бота

### Создание бота:

1. **Откройте Telegram** и найдите бота [@BotFather](https://t.me/BotFather)

2. **Создайте нового бота**:
   - Отправьте команду `/newbot`
   - Введите имя бота (например: "Тест депрессии Бернса")
   - Введите username бота (должен заканчиваться на `bot`, например: `burns_test_bot`)
   - **Сохраните токен**, который даст BotFather (выглядит как `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`)

3. **Создайте Mini App**:
   - Отправьте команду `/newapp`
   - Выберите вашего бота из списка
   - Введите название: "Тест Бернса"
   - Введите описание: "Пройдите тест депрессии Бернса и отслеживайте динамику"
   - Загрузите иконку (квадратное изображение, минимум 640x640px)
   - Когда спросит про **Web App URL**, вставьте URL из Vercel (из шага 7)
   - Готово! ✅

### Добавление кнопки в бота:

1. **Установите Python** (если еще не установлен):
   - Скачайте с [python.org](https://www.python.org/downloads/)
   - При установке отметьте "Add Python to PATH"

2. **Установите библиотеку для бота**:
```bash
pip install python-telegram-bot
```

3. **Создайте файл бота**:
   - Откройте файл `bot_example.py` в проекте
   - Замените `ВАШ_ТОКЕН_ОТ_BOTFATHER` на реальный токен
   - Замените `https://ваш-домен.vercel.app` на URL из Vercel
   - Сохраните файл

4. **Запустите бота**:
```bash
python bot_example.py
```

Бот должен запуститься! Теперь отправьте боту команду `/start` - вы должны увидеть кнопку "🧠 Пройти тест Бернса".

5. **Нажмите на кнопку** - должно открыться ваше Mini App! 🎉

## 🐛 Решение проблем

### Проблема: "npm install" не работает
**Решение**: Убедитесь, что Node.js установлен. Проверьте: `node --version`

### Проблема: "Cannot find module"
**Решение**: Выполните `npm install` еще раз в папке проекта

### Проблема: Supabase не подключается
**Решение**: 
- Проверьте, что переменные окружения в `.env` правильные
- Убедитесь, что таблица создана (SQL Editor → Run)
- Проверьте, что URL и ключ скопированы полностью

### Проблема: Mini App не открывается
**Решение**:
- Проверьте URL в BotFather - должен быть HTTPS
- Убедитесь, что приложение задеплоено на Vercel
- Проверьте, что URL правильный (без лишних пробелов)

### Проблема: График не показывается
**Решение**:
- Убедитесь, что есть сохраненные результаты (пройдите тест несколько раз)
- Откройте консоль браузера (F12) и проверьте ошибки
